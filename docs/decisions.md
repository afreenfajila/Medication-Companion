# Decisions (Phase 1–2)

Scope: local deterministic flow only. No API keys, Supabase, Claude, Gemini, camera or microphone.

## Architecture
- **Pure reducer, external store.** `src/lib/session/state-machine.ts` is a pure reducer; an illegal
  event returns the *same* session object (reference-equal), so a blocked transition is testable.
  `session-store.ts` wraps it with `useSyncExternalStore` (no setState-in-effect) and persists only
  redacted audit events + persona (sessionStorage) and language (localStorage).
- **URL never drives state.** `/companion?state=x` is compared with the session's real state and the
  URL is rewritten to match. A fresh load of `?state=explain` renders `start`.
- **Assistant text is stored as a copy key**, not a string, so the language toggle re-translates
  the current message without touching state.
- **Audit is redacted by construction:** typed text is never stored (only intent + length).

## Judgement calls (where the contracts were silent or ambiguous)
- **Matching is stricter than the scoring rule alone.** Any *provided* field that conflicts —
  including optional patient name and dosage form — is `no-match`. With only name+strength summing to
  exactly the 0.80 threshold, a wrong-patient label would otherwise still become a candidate.
- **"What is this for? When do I take it?"** routes as an unknown-medicine question (only
  `Show medicine`), per PRD §5 step 4. Schedule words alone → the two-action clarification.
- **Schedule question with a confirmed record** goes straight to the record-backed explanation
  (chunk 2); without one, `Ask about my schedule` stays in `listening` and asks for the label.
- **Contextual actions must have been offered** before `SELECT_ROUTE` is accepted.
- **Extensions to content-model types:** `help-requested` SafetyReason; audit types `call-ended`,
  `message-classified`, `route-selected`, `understanding-confirmed`; demo assets
  `sample_unreadable_label` / `sample_mismatch_label` so the safety path is reachable without a camera.
- **Chinese safety patterns** were added alongside the English ones, since the app has a 中文 mode.
- **`--color-teal-800` (#2F6B68)** added for teal *text*; `#5B9B98` is ~3.3:1 on white, below AA.
  Supporting copy uses navy-700 rather than slate-600 for the same reason.
- **Honest camera step.** "Yes, switch camera" records consent but opens no camera in this build; the
  guidance screen says so and the demo label is the way forward. Real `getUserMedia` is Phase 3.
- **Caregiver dashboard** shows seeded, badged "Sample" events until a live session exists.
- **Voice** is not offered; the listening screen says typing is the input for now.

## Deferred (later phases)
Camera/upload/typed-label UI (3), API routes + Zod envelopes + Claude (4), voice (5), deploy polish (6).

# Decisions (Phase 3 + Phase 4 pulled forward)

Request: "mock image upload, but the AI should be real." Interpreted as: bundled sample photos stand in
for the file picker; each is sent to a real server route that calls Claude vision.

- **Mock upload = bundled sample photos** (`public/samples/*.png`, fictional, generated by
  `scripts/generate-sample-labels.ps1`). The client fetches the PNG and POSTs it as multipart to
  `/api/label/analyze` exactly as a real upload would, so swapping in `<input type="file">` later is a UI-only change.
  There is deliberately no real file input in this build.
- **Claude only extracts text.** `src/lib/ai/claude.ts` (server-only) sends the image with the constrained
  system prompt from content-model §9 and a JSON-schema `output_config.format`, no tools. Output is parsed
  through a strict Zod schema; refusals, truncation, bad JSON, extra keys, SDK/network errors and a missing
  key all become `AiUnavailableError` → a 503 envelope. Model defaults to `claude-opus-5`, override with `ANTHROPIC_MODEL`.
- **The deterministic matcher still decides.** `analyzeExtraction` maps the extraction to a `LabelAnalysis`.
  A `poor` image is `unreadable` even if text came back. `notesForUser`/`ambiguityReason` are never forwarded.
- **The client trusts only the candidate id.** On `ANALYSIS_RESULT` the reducer rebuilds the candidate display
  from the local record; an unknown id or a `candidate` outcome without a payload becomes `service-failure`.
- **Failure is safe by construction:** API down / no key / timeout / malformed JSON → `service-failure` safety
  state (instructions blocked) with "Try another photo", typed details and the offline demo label available.
- **Images are never stored:** the Blob lives in a module variable for one request (`pending-image.ts`), not in
  session state, storage or the audit log. Audit records mode/source only.
- **Route hardening:** MIME allow-list, 5 MB limit (header + actual size), magic-byte sniffing (declared type must
  match the bytes), Zod-validated fields, same-origin check, per-IP rate limit (in-memory, per-instance),
  redacted server log (reason code only).
- **Camera (Phase 3):** rear camera preferred, flip only when >1 video input exists, video only (no audio),
  tracks stopped on unmount, still captured only on tap and sent through the same route. Denied/absent → explained fallback.
- **Typed labels stay local** (Zod-validated, deterministic matcher) so they work with no network.
- **Refusal fallbacks:** the `fallbacks` server parameter was not enabled — a refusal already routes to the
  safety state. Revisit if refusals show up in practice.
- **Not verified against live Claude:** no `ANTHROPIC_API_KEY` was available while building; the SDK call is
  covered by mocked tests and the no-key fail-closed path was exercised over real HTTP.

# Decisions (Phase 5, browser voice)

Scope chosen: browser voice first. Gemini Live (`/api/live/session`, `GeminiLiveProvider`) is NOT built yet;
the `VoiceProvider` interface in `src/lib/voice/provider.ts` is the seam it will implement.

- **Voice is only an input/output layer.** A recognised transcript is emitted to the same handler as typed
  text (`USER_MESSAGE`), so the call-start gate, safety classifier, intent routing and every other gate apply
  unchanged. Voice never dispatches any other event (no "say yes to confirm").
- **Nothing starts on its own.** `connect()` is a no-op; the mic is only touched by the "Tap to speak" tap;
  spoken replies are OFF until the user turns Sound on, and are only available during an active call.
- **Spoken output is never generated.** `speakableText` returns approved copy-catalogue wording and, for the
  explanation, only the record-backed text — and only when a confirmed-match `ExplanationView` exists.
  Before confirmation the possible-match screen speaks identity only.
- **Honest privacy line.** Chrome/Safari recognition may send audio to the browser vendor's service; the listening
  screen says so before the first use. Typing always works and is never disabled.
- **Controls:** Sound on/off toggle (icon + words, `aria-pressed`), Repeat re-reads the current approved content,
  changing screen/mute/end call cancels speech. Captions are always visible.
- **Unsupported browsers** (e.g. Firefox has no SpeechRecognition): mic button hidden, plain-language note,
  typing unchanged. Speech synthesis absent: no sound control.
- **Not verified with a real microphone/speaker** — the Web Speech API is exercised through fakes only. Try it in Chrome.

# Decisions (Phase 6, polish and deployment prep)

- **Contrast audit found real failures** (measured, now regression-tested against the actual tokens in
  `globals.css`): white on teal-600 badge 3.19:1, danger-700 on warning surface 3.89:1 and on canvas 4.30:1.
  Fixed with `--color-danger-800` (#943E38, 6.0:1) for small red text and a teal-800 badge. danger-700/teal-600 remain for borders/fills.
- **axe-core** runs over every companion state (14), each sheet, the typed/sample panels and all pages. It found
  one real issue: the listening screen had no `h1` (added a visually-hidden one). Colour contrast is covered by the token test
  because jsdom has no layout.
- **`/about` was wrong** after Phases 3–5 ("no AI, camera, or microphone"). Rewritten to describe Claude label reading,
  the non-AI matcher, local camera preview, browser speech and what is (not) stored.
- **Error boundaries:** `error.tsx`, `global-error.tsx`, `not-found.tsx` use calm wording and show no medicine content.
  No `loading.tsx`: pages are static, and the analysing screen is the loading state.
- **Security headers:** nosniff, X-Frame-Options DENY, Referrer-Policy, Permissions-Policy (camera/mic same-origin only).
  A CSP was deliberately not added: Next's inline bootstrap scripts need nonces, which would force every page dynamic.
- **`npm run check:bundle`** scans `.next/static` for key patterns, secret variable names and the Anthropic SDK (site-contract §15 step 6).
- **Not done:** Vercel deployment itself (needs your account), Gemini Live, Supabase, real-device screen-reader and
  keyboard passes (see `docs/demo-script.md`).
